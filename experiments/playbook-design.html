Fix-loop playbook design

Today, each iteration is one freeform claude -p call against a ~3K-token prompt; the agent decides what to Read, Edit, Bash, then commits when it thinks it's done. This document proposes a replacement: a fixed DAG of discrete steps, where each step is either orchestrator code (deterministic) or a single structured LLM call. The LLM never touches files — it returns JSON, the orchestrator applies it.

Legend.
orchestrator deterministic Python — runs every time at zero LLM cost.
LLM (irreducible) requires natural-language judgment; no heuristic suffices.
cacheable LLM LLM call whose output is keyed by content hash; the second hit on the same input never re-calls the model.
LLM today, could move currently an LLM call, but a heuristic could replace it (lower confidence; would need eval data).

1. Master flow

The outer loop is gap-kind-agnostic. After classification it dispatches to one of three playbooks. Pytest is the universal gate; on red the playbook gets exactly one retry attempt before the orchestrator gives up on the iteration.

2. The three playbooks

Each kind has its own DAG of steps. The number of LLM calls per playbook is the budget that matters: lower has 2 baseline + 1 retry, parse-error has 2 + 1, unmodeled-rule has 2 + 1. Compare to today's freeform loop which routinely consumes 10-30 turns per gap.

3. Per-step content

What each step actually does. For orchestrator steps, the command or function call. For LLM steps, the prompt skeleton + the output schema. Most of the prompt content is computed by the orchestrator from earlier deterministic steps — the LLM sees pre-digested context, never raw files.

3a. Lower-gap steps

L0 · extract AST class deforchestrator

Parse parser/ast/*.py with libcst, locate the class named in the gap label, return its source span + field list.

def extract_ast_class(label: str) -> AstClassInfo:
    bare = label.split(".")[-1]               # "AtStatement"
    for path in (REPO/"src/argentum_press/parser/ast").glob("*.py"):
        module = libcst.parse_module(path.read_text())
        cls = find_class_def(module, bare)
        if cls: return AstClassInfo(path, source=cls.code, fields=cls.fields)
L1 · list @register exemplarsorchestrator

libcst over lowerer.py: collect every @<dispatcher>.register and the body of its handler, group by dispatcher. Filter to handlers under 30 lines so the prompt stays small. Also collect every isinstance(..., ast.X) branch from _effects_from_statement so the LLM can see both patterns.

L2 · engine DSL hintsorchestrator

Existing engine_dsl_hints(): ripgrep the engine repo for the AST class name (stripped of suffixes), return top 50 lines with file:line.

L3 · summarize AST classcacheable LLM

Keyed by sha256(ast_class_source). Same class hashes to the same summary even across iterations, so this only ever costs once per AST class in the whole project's lifetime.

PROMPT (~400 tokens)
"Here is an AST class from argentum-press. Summarize what MTG concept it
represents in one sentence, and list 2-3 existing handlers it most resembles.

AST CLASS SOURCE
{{ast_class_source}}

EXAMPLES OF EXISTING HANDLER PATTERNS
{{handler_exemplars}}

Return JSON exactly:
  {{ summary: str, mtg_term: str, similar_handlers: [str, str, str] }}"
L4 · choose strategyLLM

One of three strategies: full (real DSL call), stub (emits something the engine can compile but is semantically a no-op, lets the gap move past this class), or sub-gap (delegate to an inner emitter that will surface its own gap next iteration).

PROMPT (~600 tokens; reuses L3 cached summary)
"Decide strategy for handling {{ast_class}}.

L3 SUMMARY
{{summary}}

ENGINE HINTS (top 50 ripgrep hits in argentum-engine for {{keyword}})
{{engine_hints}}

RECENT FIX COMMITS for similar classes
{{recent_diffs}}

Return JSON exactly:
  {{ strategy: 'full' | 'stub' | 'sub-gap',
     target_dsl_symbol: str,    # e.g. 'Effects.At'
     justification: str }}"
L5a · pick insertion patternLLM today, could move

Two patterns exist in lowerer.py: @dispatcher.register def _(...) handlers (one per AST class) and isinstance(stmt, ast.X): return ... branches inside helper functions like _effects_from_statement.

Heuristic candidate. Classes ending in Statement that appear inside _effects_from_statement exemplars → isinstance-branch. Classes ending in Ability / Expression → @register. A simple rule over the L1 exemplar list gets this right for most cases (~90% based on git history). Move to orchestrator only after eval data confirms the heuristic isn't dropping signal.

libcst transformer: locate the function and the anchor branch, splice body_python in. Update import section if new_imports is non-empty. Writes the file. No git commit yet.

Fires only when L7 returns nonzero. Given the original plan and the pytest output, return a revised plan with the same schema as L5.

{{plan_from_L5}}

{{pytest_output}}

3b. Parse-error steps (summarised)

StepKindWhat it does
P0orchAlready done — parse_error_block exists.
P1orchKeyword-rank parent rules. Tokenize the failing context, intersect with each rule's literal terminals, score by overlap.
P2orchFor top 3, dump full rule definition with line numbers.
P3could movePick which of the top-3 ranked rules to attach to. The keyword-overlap ranker from P1 picks the right rule in most cases; the LLM is needed only when ranks are tied or when no overlap exists. Move to orchestrator with a confidence threshold.
P4LLM"Write the Lark alternative." → JSON with {alternative_text, label}. Irreducible — phrasing depends on natural-language structure of the failing oracle text.
P5orchSplice the new line into grammar.py's triple-quoted string. The grammar source is one big string literal — orchestrator finds the rule's line range and inserts a new | branch.
P6orchRun pytest.
P8LLMDiagnose pytest failure + revise.
P9orchRevert + reapply.

3c. Unmodeled-rule steps (summarised)

StepKindWhat it does
U0orchRead the rule definition from grammar.py (existing grammar_rule_block).
U1orchList parser/ast/*.py classes by module (expressions, statements, abilities, etc.).
U2orchGit log for recent parser: handle <rule> commits, extract diffs.
U2bcould movePick the parent module for the new dataclass. Suffix-based: rules ending in expression → expressions.py, statement → statements.py, ability → abilities.py. Deterministic with a fallback to LLM on miss.
U3LLM"Design the AST dataclass." → JSON with {classname, fields: [{name, type}]}. Irreducible — field design is a modeling decision.
U4LLM"Write the transformer method." Given the dataclass shape from U3, emit the method body that constructs it from the lark Tree items.
U5orchGenerate the AST file, add to __init__.py, append the method to transformer.py. All via libcst.
U6orchRun pytest.
U8LLMDiagnose pytest failure + revise both class + handler.
U9orchRevert + reapply.

4. Why this is different from "just shrink the prompt"

  • The cache. L3 (AST class summary) is the biggest win — the same class hashes to the same summary, so over 10 lower-gap iterations touching the same neighbouring classes, you call the LLM once for each summary, not 10×.
  • Replayability collapses. Today a replay re-runs a 15-turn freeform conversation. Under the playbook, replay is just re-feeding L4 and L5 with the same inputs — the orchestrator steps are pure functions.
  • Prompt A/B becomes step A/B. Instead of comparing two full prompts you compare two L5 prompts (or just L4). The signal per dollar is much cleaner.
  • Failure is local. Today a bad agent call corrupts a file. Under the playbook, the orchestrator owns the edit — if L5's JSON doesn't fit the schema, the LLM call retries; if libcst fails to apply, the orchestrator falls back to the freeform path for that one iteration without losing state.

5. What can't move to the orchestrator

  1. Strategy choice (L4 / P3 / U3). "Should we emit a real DSL call, a placeholder stub, or delegate to a sub-emitter?" requires understanding what the engine has surfaces for and what MTG concept the AST node represents. No rule-based system handles this without becoming a reimplementation of MTG.
  2. Naming and idiom. Effects.At() vs Effects.AtPhase() vs effects.atBeginningOf(...) — judgment about engine convention. Same for grammar labels (redirectalldamageexpression vs damageredirection).
  3. Field threading. An AST class with phase, consequence, descriptor — which fields are arguments to the DSL call, which become nested handlers, which get dropped? Requires reading both sides.
  4. Parse-error phrase extraction. Recognising "all damage that would be dealt to you is dealt to enchanted creature" as a novel alternative of dealsdamageexpression is a natural-language pattern match. Heuristics give a shortlist; the LLM picks the right one.
  5. Retry diagnosis. Reading a pytest traceback and deciding "the handler shape was wrong" vs "the import name is misspelled" vs "the upstream AST has changed" is interpretive. Can't move to code without a much richer test infrastructure than we have.

Everything else — context gathering, file editing, import management, pytest, commits, cache invalidation, retries — runs on the orchestrator with no LLM involvement.
